# План миграции данных для доменных сервисов

## Контекст
Монолит `GoFuture` содержит >500 млн строк исторических данных в единой PostgreSQL БД. Прямой dump/restore приведёт к окну простоя >12 часов, что недопустимо при SLA 99.95%. Требуется миграция с нулевым/минимальным downtime, гарантией целостности и возможностью отката на каждом этапе.

## Требования
- Миграция данных для каждого из 8 доменов без остановки бизнес-процессов.
- Обработка больших объёмов данных (chunked transfer, online schema changes).
- Механизм rollback на любом этапе cut-over.
- Поддержка dual-write до финального переключения.
- Валидация консистентности до и после миграции.

## Решение

### Поэтапный алгоритм миграции (универсальный для всех доменов)
| Этап | Действие | Технологии | Длительность |
|------|----------|------------|--------------|
| **1. Подготовка** | Анализ объёмов, выбор ключей партиционирования, настройка CDC | Debezium, PostgreSQL Logical Replication | 1–2 дня/домен |
| **2. Инициализация** | Создание target-схемы, запуск Debezium-коннектора, baseline snapshot | Kafka Connect, Flyway | 3–6 часов |
| **3. Dual-Write + Sync** | Монолит пишет в обе БД. CDC синхронизирует исторические данные в фоновом режиме | Outbox Pattern, Idempotent Consumers | 2–4 недели |
| **4. Валидация** | Сверка checksums, replay тестов, проверка консистентности бизнес-правил | Custom Scripts, Great Expectations | 1–2 дня |
| **5. Cut-Over** | Короткое RO-окно (≤5 мин), остановка dual-write, переключение Gateway на новый сервис | Feature Flags, Connection Pool Drain | ≤15 мин |
| **6. Архивация** | Очистка legacy-таблиц, перевод в cold-storage, отключение CDC-коннектора | S3 Glacier, PostgreSQL Vacuum | 1–2 дня |

### Доменно-специфичные нюансы миграции
| Домен | Объём данных | Стратегия миграции | Критичность консистентности |
|-------|-------------|-------------------|----------------------------|
| `Notification` | Средний (логовые записи) | Фильтрация по TTL (перенос только активных подписок), архивация старых >90 дней | Eventual |
| `Geography` | Высокий (гео-индексы) | Выгрузка только справочников зон и кэшей маршрутов, пересчёт индексов на целевой ES | Eventual |
| `Driver` | Средний | Миграция профилей + статусов по `driver_id`. Верификация KYC-документов синхронизируется отдельно | Strong |
| `Booking` | Очень высокий | Партиционирование по `trip_date`, миграция активных поездок (≤30 дней), архивация старых в ClickHouse | Strong |
| `Pricing` | Низкий | Перенос правил и мультипликаторов, кэш Redis прогревается параллельно | Eventual |
| `Payments` | Высокий | Строгий sequential cut-over. Миграция только открытых транзакций, исторические данные реплицируются async | Strong |
| `Fraud` | Средний | Перенос blacklists и rules-sets. ML-модели переобучаются на новой схеме после миграции | Strong |
| `Analytics` | Очень высокий | Не мигрируется в PostgreSQL. Прямая настройка ELT из Kafka → ClickHouse, legacy-данные бэкапятся | N/A |

## Альтернативы
| Вариант | Плюсы | Минусы | Причина отклонения |
|---------|-------|--------|-------------------|
| Big-Bang Dump/Restore | Простота реализации, гарантированная консистентность | Downtime >12ч, высокий риск при откате, блокировка бизнеса | Не соответствует NFR (MTTR <1ч, 99.95% SLA) |
| Application-Level Dual-Write без CDC | Быстрый запуск, контроль на уровне кода | Риск рассинхрона при падении БД, сложная обработка ошибок, блокировки транзакций | Нарушает принцип надёжности доставки и KISS |
| Прямая PostgreSQL Logical Replication на уровне таблиц | Низкая задержка, native feature | Жёсткая привязка к схеме монолита, невозможность изменения структуры без остановки | Нарушает принцип независимости доменов |

## Компромиссы
- **Временное увеличение IO/CPU**: Dual-write и CDC добавляют ~15% нагрузки на legacy-БД до момента cut-over.
- **Окно eventual consistency**: В период dual-write возможны задержки репликации ≤2 сек. Компенсируется idempotent операциями и retry-логикой.
- **Сложность отладки**: Трассировка данных через 3 узла (App → Kafka → Target DB) требует детального observability (OpenTelemetry + Debezium metrics).

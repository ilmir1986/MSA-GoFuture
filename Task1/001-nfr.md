## Нефункциональные требования

| Категория                             | Требование                                                                                                                      | Метрика / Критерий приёмки                                                                                                                      |
|---------------------------------------|---------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| **Производительность**                | Обработка пиковой нагрузки                                                                                                      | ≥500 000 конкурентных поездок; P99 latency <500 мс для критических эндпоинтов (создание бронирования, обновление локации)                       |
| **Доступность**                       | Время работы критических сервисов                                                                                               | 99,95% monthly SLA; MTTR ≤1 час; автоматическое восстановление при сбоях                                                                        |
| **Масштабируемость**                  | Горизонтальное масштабирование                                                                                                  | Автоматическое добавление инстансов по метрикам (CPU, memory, RPS); время масштабирования <3 минут; поддержка ≥3 географических регионов        |
| **Time-to-Market**                    | Скорость доставки новых функций                                                                                                 | ≤2 недели от идеи до продакшена; независимый деплой сервисов                                                                                    |
| **CI/CD**                             | Время сборки и деплоя                                                                                                           | Сборка ≤15 минут; деплой на регион ≤5 минут; откат ≤2 минут                                                                                     |
| **Консистентность данных**            | Гарантия целостности                                                                                                            | Strong consistency для платежей и бронирований; eventual consistency для аналитики, геоданных, уведомлений                                      |
| **Безопасность и комплаенс**          | Соответствие регуляторике                                                                                                       | Хранение PII в регионе происхождения; шифрование данных at-rest и in-transit (TLS 1.3); аудит-логирование всех операций с персональными данными |
| **Наблюдаемость**                     | Покрытие метриками и трассировкой                                                                                               | 100% покрытие критических бизнес-путей метриками; E2E tracing через OpenTelemetry; алертинг по SLO                                              |
| **Стоимость инфраструктуры**          | Оптимизация unit-экономики                                                                                                      | Снижение стоимости обработки одной поездки на 40% за счёт автоскейлинга, spot-инстансов и эффективного кэширования                              |
| **Интеграции**                        | Работа с внешними сервисами                                                                                                     | Изоляция сбоев внешних провайдеров (платежи, карты, push) через circuit breaker; fallback-логика при недоступности                              |
| **Динамическое ценообразование**      | Пересчёт тарифов в реальном времени на основе спроса/предложения                                                                | Время расчёта новой цены ≤200 мс; обновление тарифов в кэше ≤1 сек; гарантия отсутствия дублирующих пересчётов (идемпотентность)                |
| **Умное перераспределение водителей** | Алгоритм матчинга с оптимизацией загрузки в часы пик (предпочтение сбалансированного распределения над географически ближайшим) | Время формирования рекомендации водителю ≤300 мс; снижение концентрации в «горячих зонах» на ≥25%; свежесть данных геопозиций ≤2 сек            |
